# A. 当前技术方案的尖锐审查结论

## A.1 总判断

现有项目已经形成一套不同于论文生成器的可信科研基础设施雏形，但旧技术方案把最有竞争力的机制埋在长篇方法描述、代码路径和 q001 数学细节中。评委容易先看到“Qwen＋RAG＋多智能体”，而看不到真正的差异：**系统把证据、计划、观测、评审和交付建模为可验证状态，并以 checkpoint、数字/引用守卫及三层门禁决定状态能否跃迁。**

当前最有说服力的结果不是“自动得出突破性结论”，而是：

1. 125/125 个 Science 前沿问题均形成结构化研究计划，并分别交付 Markdown 和 PDF；
2. q001 完成真实探索性 pilot，保存原始数据、四类零模型、日志、参数、指标和 manifest；
3. q001 独立评审给出 `major revision`，系统保留负面意见并阻断自动交付。

“能停下来、能留下依据”比预设成功的演示更能证明科研门禁真实生效。

## A.2 当前核心价值主张

**把大模型的科研推理转化为可追溯、可复核、可阻断、可迭代的科研状态流，使“生成建议”升级为“依据真实证据推进下一步研究”。**

## A.3 已有创新及其表达问题

- 已写出：Qwen 多阶段推理、文献/数据绑定、多智能体与 Skills、真实 pilot、独立评审、多格式交付、Science 125 问任务化。
- 未突出：科研状态契约、原始证据/派生记忆分离、计划/观测分离、临时最小权限、Skill 路由哈希、数值守卫、引用精确投影、不可变失败产物。
- 表达问题：创新散落在正文，没有统一使用“问题—机制—证据—价值—边界”；代码路径和 q001 数学细节抢占主叙事；评估指标只列名称，未区分已测与待测。

## A.4 容易被误读的部分

| 容易造成的误解 | 旧稿原因 | 新稿必须表达的差异 |
|---|---|---|
| “只是 RAG” | 文献检索篇幅大，状态契约不突出 | 检索只决定输入；证据哈希、状态和门禁决定能否继续流转 |

| “q001 证明了数学猜想” | 数学指标压过系统边界 | q001 是可信闭环压力测试，不构成任何素数猜想证明 |

## A.5 只有设计/代码、缺少实测的内容

- Skill 受控进化：有开发/隐藏分区、影子评估、晋级/拒绝代码契约，缺完整真实晋级运行链。
- 人类责任门禁：有接口与流程，缺可匿名展示的签署/拒绝样本。
- checkpoint 恢复：有阶段文件与重入机制，缺故障注入后的恢复率、时延与一致性统计。
- 模型可替换：配置读取 `base_url`、`api_key`、`model_name`，缺跨供应商同题对照。
- 工程与人因：缺单题成本、耗时、人工修改次数和多轮反馈质量曲线。

## 【P3 项目总览】

### 项目定位

AutoResearch 不是“自动写论文”的聊天机器人，而是一套证据优先的 AI Scientist 科研状态机：以 Qwen 承担规模化推理，以临时智能体与 Skills 执行方法，以证据哈希、checkpoint、数值/引用守卫和三层门禁约束每一次状态跃迁。

### 三个核心问题

1. **证据漂移：**文献事实、模型推断与实验观测容易混写。
2. **过程不可复核：**多轮生成覆盖中间状态与失败原因。
3. **自动化无边界：**结构合规、科学合理和责任授权被混为一谈。

### 六个核心创新

科研状态契约；临时智能体与可审计 Skills；原始证据/派生记忆分离；十二阶段不可变闭环；数值/引用守卫与三层门禁；确定性交付与跨领域任务编译。

### 最小可信科研闭环

科学问题 → 证据锁定 → 候选假设 → 可执行计划 → 真实 pilot 或待执行协议 → 独立评审 → 交付/阻断；评审问题以点线反馈为下一轮任务，不能覆盖旧版本。

- q001 完成 1 项真实探索性 pilot；设置 4 类零模型；
- 独立评审为 `major revision`；自动交付已阻断。

## 【P4 赛题挑战、设计目标与创新总览】

# 1. 赛题挑战与现有方案缺口

## 1.1 从开放问题到可证伪任务

常见系统给出泛化建议，却不明确分析单位、变量、对照、判据和停止条件。AutoResearch 使用任务编译 Schema 固化科学目标、竞争解释、数据、基线、指标、资源与终止条件。

## 1.2 证据进入推理链

检索内容、模型记忆和真实观测不能混写。系统锁定引用目录；原始证据不可覆盖；派生记忆只导航，不得升级为证据。

## 1.3 反馈必须改变状态

评审不是文末装饰。checkpoint 与阻断回执使评审结论直接决定交付、修订或停止。

# 2. 核心设计目标

- G1 可检查：每个结论可定位到对象、文件与哈希。
- G2 可验证：假设带有对照、指标和反证条件。
- G3 可迭代：评审与观测形成下一轮显式输入。
- G4 可负责：高风险执行和交付必须经过责任门禁。

# 3. 核心创新总览

六项创新分别处于运行级、代码级或待验证级。q001 状态与阻断、125 题双格式交付属于运行级；状态 Schema、原始/派生分离、最小权限、守卫和确定性渲染属于代码级；Skill 晋级效果、批量守卫性能、恢复、跨模型消融、成本与人工修改量属于【待补实验】。

> **创新点**：RAG 决定“取回什么”，多智能体框架决定“谁与谁通信”；AutoResearch 进一步决定什么可被认定为证据、当前处于何种科研状态、能否跃迁、失败如何保留、谁对执行和交付负责。

## 【P5 系统总体架构】

# 4. 系统总体架构

## 4.1 五层架构与三类流

1. **交互层：**接收 Science 125 问、数据/仪器入口、模型配置和人类反馈授权。
2. **编排层：**维护科研状态机、十二阶段 checkpoint、重试恢复和三层门禁。
3. **临时智能体层：**目标收窄、文献、假设、批评、规划、执行、分析、独立评审和写作投影。
4. **Skills 层：**认知 Skill、方法 Skill、治理 Skill。
5. **证据与基础设施层：**原始文献/数据/日志/manifest、Obsidian 兼容知识库、版本库、沙箱、Qwen 和领域适配器。

数据/产物流使用青绿实线；权限流使用深蓝虚线；反馈/阻断流使用红色点线。结构/溯源、独立评审、权限/安全是三个可真实失败的阻断点。

## 4.2 Qwen 与可替换边界

Qwen 是当前推理核心，承担问题收窄、假设生成和计划修订等认知任务。代码从配置读取 `base_url`、`api_key`、`model_name`；密钥不进入产物与版本库。尚无跨供应商同题质量、时延和成本对照，因此“可替换”只表示接口能力。

> **架构判定原则**：任何智能体都不能仅凭自然语言“宣布成功”改变科研状态；状态提升必须由编排层读取结构化回执和已验证证据，并满足相应门禁。

## 【P6 证据图谱与科研状态契约】

# 5. 证据图谱与科研状态契约

## 5.1 对象关系

科学目标、文献证据、数据文件、执行日志、候选假设、研究计划、观测、独立评审、决策和版本分别建模。可信状态可抽象为：

`S_t = <id, type, payload, evidence_bindings, parent_hash, artifact_hash, status>`。

下游只能引用已验证的 `S_t`；字段变化产生新哈希和新版本，不能静默覆盖旧状态。

## 5.2 三组强制分离

1. **原始证据/派生记忆：**`derived_context_is_evidence=false`；摘要可检索，不可替代文献、数据或运行记录。
2. **计划态/观测态：**没有兼容适配器时必须写明“未执行”；交付校验拒绝虚构结果图和数字。
3. **作者修订/独立评审：**评审器不重写作者产物，独立保存 recommendation 和证据清单。

> **运行证据**：q001 独立评审记录 18 个已验证文件和文件集合哈希；引用检查为 `verified_exact_union`；评审与阻断回执作为新对象保存。

## 【P7 临时智能体与可审计 Skills】

# 6. 临时智能体与可审计 Skills

## 6.1 临时智能体生命周期

任务编译 → 角色授权/最小权限 → 固定顺序上下文装配 → 受限执行/工具白名单 → Schema 回执/输出哈希 → 清理或销毁/审计回执。

固定上下文顺序为：角色政策 → 任务字节 → 允许 Skills → 锁定文献 → 派生导航 → 已验证 pilot → 输出 Schema。

## 6.2 Skills 类型

- **认知 Skill：**收窄问题、设计反证、创新性三角审查和竞争解释。
- **方法 Skill：**统计检验、数据处理、仿真/实验协议和终止条件。
- **治理 Skill：**引用锁定、数值守卫、权限检查和交付验证。

Skill 路由保存理由、来源、版本、内容哈希、输入/输出 Schema 和工具权限。

## 6.3 受控 Skill 进化

真实文献与 pilot 证据 → 候选 Skill/版本与哈希 → 隐藏证据影子评估 → 晋级或拒绝/回滚。安全策略、审批门禁和发布规则不能由 Skill 自我修改。

> **运行证据**：q001 保存 3 份假设阶段、1 份 post-pilot 临时交互；选定方法 manifest 记录 Skill 来源和哈希。
> **当前边界**：完整真实晋级链未发现，效果【待补实验】。

## 【P8 科研状态机】

# 7. 十二阶段科研闭环与状态机

## 7.1 科研状态机

问题已接收 → 证据已锁定 → 候选假设已评议 → 计划态 → 可执行态 → 执行完成 → 观测已验证 → 独立评审完成 → 责任授权 → 正式交付/执行。

评审为 `major revision`、`reject` 或不清晰时进入阻断态；执行失败生成 failure artifact；评审问题形成修订任务候选并回到证据阶段。

### q001 路径

问题 → 证据 → 假设/计划 → 真实探索性 pilot → 指标验证 → 独立评审 → `major revision` → 阻断。没有创建正式交付报告。

### 其余 124 题路径

完成问题编译和研究计划后保持 `plan-only`；没有兼容真实预实验适配器，不生成观测值或结果图。

## 7.2 状态不变量

证据不降级；观测不伪造；失败不覆盖；授权不继承。任何重试都不能绕过这些约束。

## 【P9 十二阶段不可变 checkpoint】

## 7.3 十二阶段闭环

1. 宽域文献检索；2. 研究焦点收窄；3. 定向文献检索；4. 参考目录锁定；5. Skill 路由；6. 候选假设脑暴；7. 临时研究计划；8. 真实 pilot/待执行协议；9. pilot 后客观复盘；10. 证据约束修订；11. 确定性渲染；12. 独立科学评审。

每阶段保存 checkpoint 与哈希。执行失败生成 failure artifact；评审阻断生成 review/block receipt。下游若要改变上游结论，只能创建新版本并保留差异。

### 三类反馈

- 机器：Schema 缺字段、引用越界、数字无来源、manifest 漂移——立即拒绝。
- 科学：零模型不足、方法引用不匹配、创新性检索不足、外推过度——分级并阻断或创建修订入口。
- 人类：仪器、伦理、私有数据、云资源、公开发布——明确授权后才升级状态。

> **当前边界**：q001 已验证“真实 pilot → 独立评审 → 阻断”，尚未自动完成“修订 → 再执行 → 再评审”。

## 【P10 真实执行、数值守卫与三层门禁】

# 8. 真实执行、数值守卫与三层门禁

## 8.1 从计划到观测

预注册计划 → 领域适配器/沙箱或受控仪器 → 原始数据/日志/环境 → metrics＋manifest＋SHA-256。报告中的 `[[pilot:path]]` 占位符只能从已验证字段解析；数值守卫拒绝无来源数字；引用目录锁要求引用是精确投影。

## 8.2 三层门禁

1. **机器门禁：**判断 Schema、文件、数字、引用和 manifest 是否完整一致。
2. **科学门禁：**独立、非重写地判断方法、零模型、统计解释和创新性。
3. **人类门禁：**判断真实仪器、伦理数据、资源与正式发布是否获得责任授权。

任一阻断性失败均不得自动交付。

> **已发生：q001**。真实计算产生原始 CSV、四类零模型 CSV、日志、参数、环境、metrics 和 manifest；独立评审为 `major revision`；`delivery_report_created=false`。
> **尚未量化**：数字扰动检出率、引用越界率、数值守卫误报率、人类签署样本和门禁时延【待补实验】。

## 【P15 安全边界、应用价值与下一阶段】

# 13. 安全边界、应用价值与下一阶段计划

## 13.1 安全边界

最小权限；证据不可覆盖；危险动作审批；密钥隔离；受控 Skill 进化；责任可追溯。默认沙箱；未授权时不操作真实仪器、不访问私有数据、不租用云 GPU、不提交论文、不公开发布。

## 13.2 应用价值

- 前沿问题预研：把宽问题编译为带证据、基线、指标、停止条件的方案集合；不替代专家判断。
- 计算/仿真研究：形成原始产物—指标—评审链；不替代模型有效性和资源授权。
- 实验协同与项目治理：保存进度、失败、版本差异和下一轮任务；不替代伦理、仪器与发布责任。

## 13.3 下一阶段路线图

- 阶段 I（0—4 周）：125 题 Schema/manifest 复核；数字/引用对抗；20 题最小消融。
- 阶段 II（1—3 月）：q001 修订—再运行—再评审；checkpoint 故障注入；人类门禁样本。
- 阶段 III（3—12 月）：为高价值题接入数据、仿真和仪器；跨实验室复现与成本评估。

## 结论

AutoResearch 已完成的不是“125 次自动科学发现”，而是 125 个可继续推进的结构化研究任务，以及一个能够暴露自身缺陷的 q001 真实闭环样本。其技术实质是让 Qwen 在证据对象、最小权限 Skills、不可变 checkpoint、数字/引用守卫和分层门禁中承担规模化认知劳动。q001 的 `major revision` 与交付阻断表明：系统的目标不是保证每次生成成功，而是保证科研状态不越过证据边界。
