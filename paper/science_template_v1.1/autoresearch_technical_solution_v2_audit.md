# AutoResearch 技术方案内容审计与缺口清单

> 审计日期：2026-08-20（Asia/Shanghai）
> 审计对象：现有技术方案 PDF、AutoResearch 源代码、Science 125 问交付目录及 q001 运行产物
> 证据分级：**A＝运行产物已验证；B＝代码契约已核验；C＝仅有设计描述；D＝尚无证据**

## A. 当前技术方案的尖锐审查结论

### A.1 总判断

现有方案已经具备一套明显不同于“论文生成器”的可信科研基础设施雏形，但文档把最有竞争力的系统机制埋在长篇方法描述、代码路径和 q001 数学细节之中。评委目前容易先看到“Qwen＋RAG＋多智能体”，而不是看到真正的差异：**以证据绑定的科研状态为主线，以不可变 checkpoint、数值与引用守卫、独立科学评审和失败保留来决定科研工作能否继续流转。**

项目当前最有说服力的结果不是“自动得出科学结论”，而是：系统已将 125 个 Science 前沿问题编译为 125 份结构化、可执行研究计划；其中 q001 完成真实探索性 pilot，独立评审给出 `major revision` 后，系统保存负面意见并阻断自动交付。这个“能停下来”的结果，比未经核验的正向演示更能证明科研门禁确实生效。

### A.2 当前核心价值主张

**把大模型的科研推理转化为可追溯、可复核、可阻断、可迭代的状态化科研流程，使“生成建议”升级为“在证据和责任门禁约束下推进下一步研究”。**

这一主张由三类现有事实支撑：

1. **规模化计划编译：**125/125 个问题均已有结构化 Markdown 与 PDF 研究计划；
2. **真实闭环样本：**q001 具有原始数据、四类零模型数据、日志、指标与 manifest；
3. **负面门禁样本：**q001 的独立科学评审为 `major revision`，自动交付被阻断，失败状态未被覆盖。

### A.3 当前已经写出的创新点

现有文档已经涉及以下内容，但表达较分散：

- Qwen 驱动的多阶段科学推理；
- 文献、数据和运行产物的证据绑定；
- 多智能体分工与 Skills 路由；
- 从问题理解到研究计划、pilot、评审和修订的科研闭环；
- Science 125 问跨领域研究计划生成；
- q001 的真实计算与多零模型检验；
- Markdown、TeX、PDF、manifest 多格式交付；
- 独立评审与交付阻断。

问题不在于“没有创新”，而在于这些内容没有被归并成可审查的一级创新，也没有稳定使用“问题—机制—证据—价值—边界”的表达格式。

### A.4 代码或运行产物已支持、但文档没有突出表达的创新

1. **科研状态契约与内容哈希绑定（B）：**研究计划、产物和输入通过稳定字段、`input_hash`、`artifact_hash` 与文件哈希形成显式契约，而非依赖聊天上下文。
2. **原始证据与派生记忆分离（B）：**原始字节和不可变信封保留；派生摘要被声明为 `derived_context_is_evidence = false`，只能用于导航。
3. **计划态与观测态分离（A/B）：**批处理在没有兼容真实适配器时必须写明“未执行预实验”；交付校验器拒绝把待执行计划写成观测结果。
4. **临时最小权限智能体（A/B）：**任务对象显式携带角色、输出 Schema、Skill 上下文、证据子集和上下文预算；任务结束生成清理或紧急回执。q001 中存在临时智能体交互记录。
5. **可审计 Skill 路由（A/B）：**Skill 选择具有路由理由、内容哈希、分层来源与容量上限；q001 运行中存在版本化 Skill manifest。
6. **十二阶段 checkpoint 与失败产物（A/B）：**阶段产物被逐段保存，后续状态显式引用前序对象；评审失败不会被下一次生成覆盖。
7. **数值占位符解析与证据守卫（A/B）：**计划中的 pilot 数值从经验证的指标文件绑定，关键数字无法回溯时触发拒绝。
8. **锁定引用目录（A/B）：**引用必须是锁定目录的精确投影，未知引用采用 fail-closed 策略。
9. **独立非重写科学评审（A/B）：**评审调用不负责替作者改稿，结果独立保存；`major revision` 属于阻断性建议。
10. **确定性多格式渲染与清单复核（A/B）：**同一结构化对象输出 Markdown、TeX、PDF 与清单，并记录源哈希和证据绑定哈希。

### A.5 当前只有设计或代码描述、缺少实测数据的内容

- **Skill 受控进化：**代码中存在开发证据/隐藏证据分区、影子评估与晋级条件，但尚未发现一次完整的候选 Skill 生成—隐藏集评估—晋级/拒绝运行产物。当前只能表述为“已实现代码契约，真实晋级效果【待补实验】”。
- **三层门禁的“人类责任授权”：**机器校验与独立科学评审已有实现和运行证据；最终人类责任门禁具有校验接口，但尚无可匿名展示的人类签署/批准记录。
- **checkpoint 恢复：**存在 checkpoint 文件与重入机制，但尚无故障注入后的恢复成功率、恢复时间或一致性测试。
- **跨模型可替换性：**配置支持 `base_url`、`api_key`、`model_name`，但尚无同题跨供应商对照数据。
- **质量提升与成本收益：**尚无多轮反馈质量曲线、人工修改次数、单题成本和单题完成时间的系统统计。

### A.6 容易被误认为普通 RAG、多智能体编排或 Prompt 工程的部分

| 容易造成的误解 | 当前呈现问题 | 必须改写为 |
|---|---|---|
| “只是 RAG” | 文献检索与上下文增强篇幅较大，证据对象状态不突出 | 检索只是输入；决定能否流转的是证据哈希、状态契约、数字/引用守卫和门禁 |
| “只是多个 Agent 串起来” | 角色列表比权限和生命周期更醒目 | 临时创建、最小权限、受限上下文、结构化回执、销毁与审计形成完整生命周期 |
| “只是复杂 Prompt” | 认知方法和规则像提示词模板 | Skills 是有版本、哈希、来源、预算和路由理由的执行单元，不等于一段自由文本 |
| “只是批量写 125 份报告” | 计划数量容易被误读为实验规模 | 明示 125 份研究计划、124 题计划态、1 题真实探索性 pilot；计划不等于观测 |
| “q001 得出了数学新结论” | 统计细节压过边界声明 | q001 是可信闭环压力测试；没有证明任何素数猜想，结果只支持下一轮研究决策 |

### A.7 当前缺失的系统评估、消融、竞品对比和工程指标

当前已有可报告数据主要是交付覆盖、q001 运行文件与指标、引用完整性结论、独立评审和阻断状态。以下指标尚不能给出实测百分比：

- JSON/Schema 级完整率；
- 引用目录越界率；
- 关键数字可追溯率；
- 数值守卫拒绝率；
- 计划态误写为观测态发生率；
- manifest 批量复核通过率；
- checkpoint 故障恢复成功率；
- 独立评审阻断率的代表性统计；
- 单题生成成本与完成时间；
- 人工修改次数；
- 多轮反馈后的质量提升；
- 模型、Skill、门禁和记忆配置消融；
- 与外部系统的同任务、同预算对比。

这些缺口不得用推测性数字填补，应在正文评估矩阵中标记为【待补实验】，并给出可执行的验证设计。

### A.8 所有潜在过度表述与处理意见

| 风险表述 | 风险 | 改写要求 |
|---|---|---|
| “完成 125 项 pilot/实验” | 将计划态误写为观测态 | 改为“完成 125 份结构化研究计划；q001 完成真实探索性 pilot” |
| “证明/验证了素数猜想” | q001 不具备该结论 | 删除；明确“未证明任何素数猜想” |
| “全自动科学发现” | 人类授权与真实实验覆盖不足 | 改为“在证据与门禁约束下辅助推进下一步研究” |
| “首个、首创、领先、SOTA” | 无直接优先权或基准证据 | 删除或标记【待补证】 |
| “全面优于 AI Scientist” | 无同任务对比实验 | 仅比较公开材料中明确披露的机制，不作总体优劣结论 |
| “Skill 已能自我进化” | 缺完整晋级运行证据 | 改为“已实现受控进化代码契约；真实晋级效果【待补实验】” |
| “三层门禁均已通过验证” | 人类门禁缺签署样本 | 分层报告证据状态，不合并夸大 |
| “可完全复现” | 缺跨环境批量复现实验 | 改为“保存复现所需清单与哈希；跨环境复现率【待补实验】” |

## B. 创新—证据矩阵

### B.1 一级创新 1：证据绑定的科研状态契约

| 字段 | 审计结果 |
|---|---|
| 解决的问题 | 对话历史不可稳定复核；摘要可能覆盖原始事实；计划文本可能被误写为已观测结果 |
| 核心机制 | 将科学目标、证据对象、计划、观测、决策和评审建模为结构化对象；用稳定 ID、输入哈希、产物哈希和文件哈希绑定；原始证据不可覆盖，派生记忆仅用于导航；计划态与观测态显式分离 |
| 与普通方案的区别 | RAG 主要解决“取回什么上下文”；本机制解决“哪个对象可被当作证据、处于什么状态、能否进入下一阶段” |
| 代码实现 | `contest_direct_plan.py`；`knowledge/raw_memory.py`；`contest_direction_memory.py`；`science125_batch.py`；`contest_human_delivery_validator.py` |
| 运行产物 | q001 的 `environment.json`、`manifest.json`、`metrics.json`、参数、原始/零模型 CSV；125 题 Markdown/PDF 计划集 |
| 当前证据状态 | **A/B**：代码契约已核验；q001 有真实证据链；125 题有计划态披露 |
| 尚缺验证 | 125 题结构化对象批量 Schema 校验；跨环境哈希复核；计划/观测混淆对抗测试 |
| 评委价值 | 能从报告中的数字追到输入文件与状态来源，降低“模型说过即事实”的风险 |
| 当前边界 | 现有 125/125 统计证明的是文档必备章节完整，不等同于所有内部 JSON Schema 均已批量实测通过 |

### B.2 一级创新 2：临时最小权限智能体与可审计 Skills

| 字段 | 审计结果 |
|---|---|
| 解决的问题 | 常驻智能体权限过大、上下文污染、方法选择不可解释、任务完成后难以追责 |
| 核心机制 | 按任务创建智能体；按角色装配必要 Skill、证据子集、输出 Schema 和上下文预算；执行后输出结构化回执并清理；Skill 路由记录理由、版本、内容哈希和来源 |
| 与普通方案的区别 | 重点不是 Agent 数量，而是权限边界、上下文边界和执行后可审计性 |
| 代码实现 | `temporary_qwen_pool.py`；`contest_direct_skill_router.py` |
| 运行产物 | q001 的假设生成与 post-pilot 临时交互记录；`selected-methods.json`/Skill manifest（含哈希） |
| 当前证据状态 | **A/B**：生命周期和路由契约有代码；q001 有交互与 Skill 路由产物 |
| 尚缺验证 | 权限越界对抗测试；有/无 Skill 路由消融；上下文预算—质量—成本曲线 |
| 评委价值 | 让多智能体从“角色扮演”转为可约束、可复核的科研执行单元 |
| 当前边界 | 尚无跨 125 题统一汇总的权限违规率或清理成功率 |

### B.3 一级创新 3：受控 Skill 进化

| 字段 | 审计结果 |
|---|---|
| 解决的问题 | 自我修改可能把错误经验、数据泄漏或不安全规则固化为系统能力 |
| 核心机制 | 候选 Skill 只能从文献与 pilot 证据提炼；开发证据与隐藏证据分区；候选只进入影子评估；隐藏集通过后才具备晋级资格；安全和授权规则禁止自我修改 |
| 与普通方案的区别 | 不是把一次成功 Prompt 直接写回系统，而是通过证据来源、隐藏评估和晋级条件控制知识沉淀 |
| 代码实现 | `contest_direction_skill_evolution.py` |
| 运行产物 | 未发现完整的候选生成—隐藏集评估—晋级/拒绝 artifact 链 |
| 当前证据状态 | **B（代码契约）/【待补证】（运行效果）** |
| 尚缺验证 | 至少 20 个候选 Skill 的盲测；记录接受率、隐藏集提升、回归失败、回滚结果和人工复核意见 |
| 评委价值 | 给“系统自我提升”设置可审计、可回滚的科学边界 |
| 当前边界 | 不得写成“系统已自主进化并提升性能” |

### B.4 一级创新 4：不可变十二阶段科研闭环与负面结果保留

| 字段 | 审计结果 |
|---|---|
| 解决的问题 | 长流程失败后难定位；重新生成会覆盖失败；正向结果偏倚导致科研过程不可复核 |
| 核心机制 | 十二阶段逐级 checkpoint；下游显式引用上游对象；失败生成正式 artifact；评审意见和阻断回执成为下一轮任务输入 |
| 与普通方案的区别 | 普通工作流关注“最终答案”；本机制把中间状态、失败原因和恢复入口都视为科研资产 |
| 代码实现 | `contest_direction_research_loop_cli.py`；阶段产物与阻断回执生成模块 |
| 运行产物 | q001 的阶段产物、独立评审 `major revision`、阻断回执和保留的修订计划 |
| 当前证据状态 | **A/B**：阶段机制有代码，q001 真实展示负面门禁链 |
| 尚缺验证 | checkpoint 故障注入与恢复；多轮评审—修订质量曲线；不同失败类型的覆盖率 |
| 评委价值 | 证明系统不仅会向前生成，也能在证据不足时停止、留下原因并组织下一轮工作 |
| 当前边界 | q001 当前未完成自动评审—自动修订—再评审的完整多轮闭环 |

### B.5 一级创新 5：数值/引用守卫与三层门禁

| 字段 | 审计结果 |
|---|---|
| 解决的问题 | 大模型可能编造数字或引用；结构通过不等于科学合理；科学合理不等于获得责任授权 |
| 核心机制 | pilot 数值以证据占位符绑定；关键数字必须存在于已验证文件；引用只能来自锁定目录；机器门禁检查结构和溯源，独立科学门禁给出非重写评审，人类门禁负责最终责任授权 |
| 与普通方案的区别 | 将“生成后人工看看”拆成职责不同、可独立失败的三层判定，任一阻断性状态均不能自动交付 |
| 代码实现 | `contest_direct_plan_revision.py`；`contest_reference_policy.py`；`contest_direct_plan_scientific_review.py`；`contest_human_delivery_validator.py` |
| 运行产物 | q001 的已验证文件清单、引用精确并集状态、`major revision` 与 `blocked_by_independent_scientific_review` 回执 |
| 当前证据状态 | **A/B**：机器与科学门禁已有直接证据；人类责任门禁为代码/流程级证据 |
| 尚缺验证 | 批量数字注入与引用越界对抗集；人类签署/拒绝的匿名化样本；三层门禁时延与误报分析 |
| 评委价值 | 把可信性从模型自述转化为可失败的工程控制点 |
| 当前边界 | 不能把存在人类门禁接口写成已有大规模人类审批实证 |

### B.6 一级创新 6：确定性交付与跨领域任务编译

| 字段 | 审计结果 |
|---|---|
| 解决的问题 | 开放科学问题难以转化为可执行协议；多格式文档之间容易漂移；规模化交付易混淆执行状态 |
| 核心机制 | 将问题编译为包含依据、数据、方法、实验、指标、停止条件和资源边界的研究任务；从同一结构化对象渲染 Markdown、TeX、PDF 和 manifest；计划态必须显式披露未执行 |
| 与普通方案的区别 | 不以自由文本建议作为终点，而以可执行任务协议和一致的交付对象作为输出 |
| 代码实现 | `science125_batch.py`；`contest_direct_plan_render.py`；相关交付校验模块 |
| 运行产物 | 125/125 份 Markdown 与 PDF；q050、q091、q119 等跨领域计划样本；q001 真实 pilot 套件 |
| 当前证据状态 | **A/B**：125 题交付目录已核验；渲染与 manifest 契约有代码 |
| 尚缺验证 | 领域分布统计；专家盲评；跨环境复现；输出格式一致性批量校验；成本/时间统计 |
| 评委价值 | 证明系统可把同一可信工作流迁移到不同学科问题，而不是只演示单一问答 |

### C.3 第一优先级补证包

若赛前只能补一轮实验，建议优先完成以下四组，因为它们直接支撑“可信科研基础设施”的主张：

1. **125 题批量 Schema/manifest 复核**：成本低，能够把“章节完整”提升为“对象契约完整”；
2. **数字与引用对抗注入测试**：直接量化守卫的检出率和误报率；
3. **checkpoint 故障恢复测试**：验证十二阶段并非仅有文件输出，而是真正可恢复；
4. **20 题最小消融**：至少比较直接 Qwen、Qwen＋检索、完整 AutoResearch 三种配置，并由盲评专家评分。

### C.4 本轮重构的事实处理规则

- 正文只写已核验结果；缺失指标统一标记【待补实验】；
